# Component README

为开发者编写简洁、可扫描、与实现一致的组件说明。默认使用中文正文，保留 API 名称和英文技术取值；遵循用户指定的语言。

## 与组件工作流的关系

本技能只负责静态组件 README。`agentbox-component` 负责组件实现与构建流程，`component-preview-html` 负责交互预览；不要在此维护第二套构建规则或预览章节规范。

- Agentbox 双层工程中的目标是 `<atom-components|large-components>/components/<Name>/README.md`。两层使用相同文档结构，组合组件的 Usage 应引用真实 atom 源码依赖，不复制原子实现。
- 只读目标 README、实现和必要依赖；不为写文档扫描生成 HTML、其他组件或 `.history/`。
- 单独调用本技能时，纯文档变更无需加载其他技能、修改 registry、构建独立页或刷新总览。
- 由主技能协调的 API / 状态 / 默认值变更，只同步受到影响的文档章节。交互预览需同步时使用 HTML 技能，由主工作流选择构建范围；不能从“README 同步”推导出全量重建。
- 对其他目录结构，以实际源码位置为准；不因使用本技能而迁移工程。

## 先确认范围和事实

- 在用户指定的目录中查找实际组件及 README；不要假设当前工作区与用户提到的目录相同，也不要将 assets 说明、生成文件、临时副本算作组件。
- 阅读对应源码、样式、预设或类型定义及现有 README，核对参数、默认值、支持的组合、图标能力和状态管理边界。
- 区分实现限制与设计约定。例如代码允许传入某形状，但规范限定其适用组合，应写“按设计规范”，不要写成代码会强制回退。
- 使用 Material 等文档作为表达方式参考时，不要照搬组件尚未实现的 variant、尺寸、toggle、loading 或无障碍能力。
- 仅调整 Overview 或格式时，保留 Props、Color Spec、Usage 的原始内容。若发现其他部分与实现不符，说明发现；不借机修改组件实现。

## 固定文档结构

遵循这套项目约定，除非用户另有要求：

```markdown
# ComponentName

## Overview

#### 作用

用一两句话说明组件用于什么，以及必要的职责边界。

#### 视觉样式

介绍支持的样式，每个样式单独一条，包含 UX 定位和具体场景。

#### 尺寸与形状

- 可用尺寸及组合限制。
- 可用形状及设计约定或实现限制。

#### 图标

说明可选图标的位置、类型和组合限制。

#### 使用原则

说明标签、文案或该组件特有的使用原则。

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|

## Color Spec

颜色 token 与状态表现。

## Usage

可复制的代码示例。
```

- Overview 为二级标题，其内部分类明确使用四级标题 `####`，不要改成三级。
- 同类内容集中在同一小标题下：样式选项、每种样式的 UX 场景和操作层级原则都放在“视觉样式”。
- 一段说明组件作用；并列选项用列表。避免把多个 variant 的解释塞进一个长句，也不必为简短 Overview 添加场景表格。
- 分类根据组件实际能力调整：无图标则省略“图标”，无形状可将“尺寸与形状”改为“尺寸”，有行为模式可增加对应四级标题。不要填充空章节或臆造能力。
- 顶层保持这四部分，不主动扩展安装、完整无障碍指南、维护记录等章节；必要信息放入相关现有部分或链接公共文档。

## 视觉样式的 UX 写法

解释“何时选它”，不只解释颜色外观。每条使用 `取值：操作层级或用户目的 + 具体例子`。

对于具有以下四种样式的按钮，可参考：

- `filled`：用于当前区域的主操作，如保存。
- `tonal`：用于需要强调的辅助操作，如预览。
- `outlined`：用于需要明确边界的次要操作，如取消。
- `text`：用于上下文中的轻量操作，如编辑。

这只是按钮示例，须结合项目规范和组件职责调整。下拉触发器的例子应说明展开的菜单，例如新建类型或导出格式；不要暗示点击后直接完成业务操作。其他组件应说明其自身的选择、输入或展示场景，不套用按钮层级。

操作层级相关组件可说明：同一操作区域通常只保留一个高强调的主操作；同一业务动作可按场景选择不同样式。把这些写成 UX 建议，不是运行时限制。视觉样式与行为模式、选中状态、展开状态应明确区分。

## 编写其余部分时

仅在用户请求新建或修改对应部分时应用：

- **Props**：列出真实类型、默认值、用途、优先级和组合限制；不要声称未实现的原生属性透传。
- **Color Spec**：按实际 CSS 记录背景、边框、文字或图标、hover、pressed 等语义 token，补充真实的 disabled、focus 和主题差异。共享 token 使用引用，不重复定义。
- **Usage**：提供准确的导入路径和代表性示例，必要状态与回调应有定义。不要使用不存在的 props 或将纯展示状态参数作为业务接口推荐。

## 完成检查

- 核对 Overview 中每个能力和限制与源码或项目规范一致，推荐用法与当前实现清楚区分。
- 检查标题层级、列表分组及 variant 场景是否容易扫描；只列实际支持的选项。
- 局部修改时，比较并确认未请求修改的章节保持原样。纯文档格式调整无需构建组件或增加测试。
- 同步到另一目录只在用户请求时执行；按组件名称确认目标，复制后核对内容一致，不覆盖其他组件文档。
- 交付时简短列出修改内容和可点击的文件路径。
